# RPT v2.8.2

本次发布聚焦**通道级背压语义修正**、**断流关闭语义修复**，以及 **UDP 虚拟会话空闲回收优化**。

## ✨ 新特性

- **通道级背压新增绝对上限 `bufferLimit`**（Java + Go）
  在原有 `highWater` / `lowWater` 水位线之上，新增 `bufferLimit`（默认 `capacity × 8`）。对端不遵守背压导致积压越过绝对上限时，以 RST 放弃该通道，作为内存保护的最终兜底。
- **UDP 虚拟会话空闲超时可配置 `udpSessionTimeout`**（服务端）
  由写死的 60 秒改为可配置，默认 **300 秒**；填 0 或负数取默认值。见下方「配置变更」。

## 🐛 修复

- **关闭时尾部数据丢失**（Java + Go）
  对端正常结束（`TYPE_DISCONNECTED`）时，通道缓冲区里可能还压着慢读者没收走的数据，原先直接 close 会静默丢弃尾部。现在先**排空积压再发 FIN**，并带 30 秒排空停滞看门狗——停滞则改用 RST 放弃。
- **截断流被误判为正常结束**（Java + Go）
  隧道断开 / 积压超上限 / 排空停滞等「数据已不完整」的场景，由发 FIN 改为发 RST，让无长度标识的协议（HTTP 响应体、RDP 等）把截断当成失败而非正常结束。
- **ChannelBuffer 目标连接已关闭时写入泄漏**（Java）
  目标连接已关闭或会话已结束时，隧道线程再写入的数据会一直占住内存并向对端发无意义 PAUSE。现在直接 release 丢弃。

## 🔧 改进

- UDP 代理建立前的数据缓冲上限 `MAX_BUFFER_SIZE` 由 64 提到 128。
- 服务端 `UDP_LAST_ACTIVE` 活跃表挂在 UDP 通道属性上，下行由 `DataExecutor` 刷新。

## ⚙️ 配置变更

| 配置项 | 位置 | 默认值 | 说明 |
|--------|------|--------|------|
| `bufferLimit` | server.yml / client.yml（Java、Go） | `0` | 单通道积压绝对上限（字节），`0` 取 `capacity × 8`；超过说明对端未遵守背压，以 RST 放弃该通道 |
| `udpSessionTimeout` | server.yml | `300` | UDP 虚拟会话空闲超时（秒），上下行都无数据报超过该值才回收；RDP-UDP 场景不宜低于 70 |

> `capacity` 语义调整：由「兜底硬上限，触达即关闭」改为「告警线，只告警不丢数据」，绝对上限由 `bufferLimit` 承担。
